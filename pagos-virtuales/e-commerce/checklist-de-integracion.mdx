Usa este checklist como una guía rápida antes de pedir validación final al equipo de integraciones.

<Info>
  Esta guía aplica para implementaciones CMS con **WooCommerce**, **PrestaShop** y **VTEX**.
</Info>

## Seguridad y buenas prácticas

Aplica estas recomendaciones cuando integres Alignet One mediante **WooCommerce**, **PrestaShop** o **VTEX**.

## Seguridad y credenciales

<AccordionGroup>
  <Accordion title="Credenciales por ambiente" icon="key" defaultOpen>
    * Usa credenciales sandbox solo para pruebas.
    * No mezcles credenciales de Pre-Producción y Producción.
    * Restringe el acceso administrativo al panel donde se configuran llaves.
  </Accordion>

  <Accordion title="Backoffice seguro" icon="lock">
    * Mantén actualizado el CMS, plugin, módulo y dependencias.
    * Usa usuarios administrativos individuales, no cuentas compartidas.
    * Revisa logs sin exponer datos sensibles del comprador.
  </Accordion>
</AccordionGroup>

## Operación del pedido

<CardGroup cols={2}>
  <Card title="Estados consistentes" icon="database">
    El estado del pedido debe reflejar el estado real del pago, no solo la pantalla que vio el cliente.
  </Card>

  <Card title="Métodos asíncronos" icon="clock">
    Para QR, transferencia, Cuotéalo o PagoEfectivo, espera confirmación final antes de liberar el pedido.
  </Card>

  <Card title="Logs de soporte" icon="file-lines">
    Conserva número de operación, estado y fecha para trazabilidad con el equipo de integraciones.
  </Card>

  <Card title="Pruebas controladas" icon="flask">
    Valida aprobados, rechazados y pendientes en sandbox antes de pasar a producción.
  </Card>
</CardGroup>

## Antes de salir a vivo

* Revisa que el plugin o módulo esté en modo productivo solo cuando corresponda.
* Confirma que los métodos habilitados coincidan con lo afiliado para el comercio.
* Valida correos, páginas de retorno, mensajes al comprador y estados del pedido.
* Prepara evidencia mínima de pruebas para revisión final.




## Checklist base

<AccordionGroup>
  <Accordion title="1. Preparación" icon="key" defaultOpen>
    * Credenciales recibidas para el ambiente que usarás.
    * Comercio configurado con los métodos de pago habilitados.
    * Acceso administrativo a tu plataforma CMS.
    * Plugin o módulo correcto disponible para instalar.
  </Accordion>

  <Accordion title="2. Configuración funcional" icon="gear">
    * Llaves y credenciales ingresadas sin errores.
    * URLs de retorno y páginas de confirmación revisadas.
    * Moneda, país y medios de pago configurados correctamente.
    * Modo sandbox activo antes de validar compras.
  </Accordion>

  <Accordion title="3. Flujo de compra" icon="cart-shopping">
    * Compra aprobada validada de extremo a extremo.
    * Compra rechazada validada con mensaje visible para el cliente.
    * Métodos asíncronos probados si están habilitados.
    * Confirmación de pedido alineada con el estado real del pago.
  </Accordion>

  <Accordion title="4. Operación y backoffice" icon="table-columns">
    * Estados del pedido revisados desde el panel administrativo.
    * Logs o registros del plugin disponibles para soporte.
    * Reversas, extornos o devoluciones revisados si aplican.
    * Correos, mensajes o páginas post-pago revisados.
  </Accordion>

  <Accordion title="5. Producción" icon="rocket">
    * Sandbox validado antes de usar credenciales productivas.
    * Flujo productivo controlado revisado con el equipo.
    * Medios de pago habilitados coinciden con lo afiliado.
    * Integración lista para salida a vivo.
  </Accordion>
</AccordionGroup>

## Puntos por plataforma

<Tabs>
  <Tab title="WooCommerce">
    <CardGroup cols={2}>
      <Card title="Plugin y credenciales" icon="wordpress">
        Verifica instalación, activación del plugin y configuración correcta de llaves.
      </Card>

      <Card title="Checkout y pedido" icon="credit-card">
        Revisa que el checkout muestre medios válidos y que el pedido cambie de estado correctamente.
      </Card>
    </CardGroup>

    * Validar compra aprobada con redirección o confirmación final correcta.
    * Validar compra rechazada con mensaje claro para el cliente.
    * Confirmar logs del plugin disponibles para soporte.
    * Revisar comportamiento de métodos asíncronos si están activos.
  </Tab>

  <Tab title="PrestaShop">
    <CardGroup cols={2}>
      <Card title="Módulo y hooks" icon="store">
        Confirma que el módulo esté activo y disponible en el checkout correcto.
      </Card>

      <Card title="Estados del pedido" icon="clipboard-check">
        Revisa que el pedido refleje el estado del pago luego de la respuesta o notificación.
      </Card>
    </CardGroup>

    * Validar instalación y configuración del módulo desde Back Office.
    * Confirmar experiencia del cliente en pago aprobado, pendiente y rechazado.
    * Revisar actualización automática de estados y registros del módulo.
    * Probar extorno o validación operativa si el flujo lo contempla.
  </Tab>

  <Tab title="VTEX">
    <CardGroup cols={2}>
      <Card title="Configuración comercial" icon="shopping-cart">
        Revisa credenciales, condiciones de pago y configuración del conector por ambiente.
      </Card>

      <Card title="Flujo de pago" icon="arrow-right-arrow-left">
        Verifica que el checkout de VTEX complete el pago y refleje correctamente el resultado.
      </Card>
    </CardGroup>

    * Validar configuración de métodos de pago y condiciones en VTEX.
    * Revisar compra aprobada y comportamiento de reintentos o rechazos.
    * Confirmar consistencia entre orden, pago y respuesta de la pasarela.
    * Completar pruebas funcionales antes de homologación final.
  </Tab>
</Tabs>
