Use this checklist as a quick guide before requesting final validation of your **Mobile SDK** flow.

<Info>This guide applies to native **Android** and **iOS** implementations, for both payment and affiliation flows.</Info>

## Security and best practices

Apply these recommendations when integrating Alignet One through the **Android SDK** or **iOS SDK**.

## Recommended architecture

<CardGroup cols={2}>
  <Card title="Mobile app" icon="mobile-screen-button">Invoke the SDK, present the payment or affiliation flow and display user-friendly responses.</Card>
  <Card title="Backend" icon="server">Generate tokens, protect credentials, record operations and confirm final results.</Card>
</CardGroup>

<Warning>Do not include credentials, secrets or sensitive logic in the app. Keep critical functionality on the backend.</Warning>

## Mobile security

<AccordionGroup>
  <Accordion title="Tokens" icon="key" defaultOpen>
    * Generate the `Access Token` from the backend.
    * Do not persist sensitive tokens in insecure storage.
    * Avoid printing tokens or complete payloads in logs.
  </Accordion>
  <Accordion title="Private SDKs" icon="box">
    * Do not upload private `.aar`, `.xcframework` or ZIP files to public repositories.
    * Use the version provided or approved by the integration team.
    * Validate compatibility before updating dependencies.
  </Accordion>
  <Accordion title="SDK response" icon="shield-check">
    * Use callbacks or delegates to update the user experience.
    * Confirm states from the backend when required by the method.
    * Handle cancellation, errors, timeouts and returning to the app.
  </Accordion>
</AccordionGroup>

## Recommended validation

* Test Android and iOS separately.
* Validate approvals, declines and controlled errors.
* Review behavior with poor connectivity.
* Keep the operation number and minimal logs for support.

## Core checklist

<AccordionGroup>
  <Accordion title="1. Preparation" icon="key" defaultOpen>
    * Target platform defined: **Android**, **iOS** or both.
    * Technical requirements reviewed for each platform.
    * Credentials and test environment available.
    * Use case defined: payment, affiliation or both.
  </Accordion>
  <Accordion title="2. Installation and configuration" icon="gear">
    * SDK installed correctly in the project.
    * Compatible dependencies and versions validated.
    * Permissions, network configuration and sandbox environment reviewed.
    * Initialization completed without errors in the app.
  </Accordion>
  <Accordion title="3. Flow implementation" icon="code">
    * Required parameters sent in the correct format.
    * Callbacks or listeners implemented for success, decline and error.
    * Navigation and return to the app flow validated.
    * Sensitive data not exposed in the client, logs or screens.
  </Accordion>
  <Accordion title="4. Functional validation" icon="cart-shopping">
    * Approved payment flow tested successfully.
    * Declined flow or controlled error validated.
    * Affiliation flow tested where applicable.
    * Messages and user experience reviewed.
  </Accordion>
  <Accordion title="5. Production" icon="rocket">
    * Sandbox completed with minimum test evidence.
    * Final build reviewed for the production environment.
    * Minimal logs available for support and diagnostics.
    * Integration ready to go live.
  </Accordion>
</AccordionGroup>
