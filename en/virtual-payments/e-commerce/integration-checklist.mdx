Use this checklist as a quick guide before requesting final validation from the integration team.

<Info>This guide applies to CMS implementations with **WooCommerce**, **PrestaShop** and **VTEX**.</Info>

## Security and best practices

Apply these recommendations when integrating Alignet One through **WooCommerce**, **PrestaShop** or **VTEX**.

## Security and credentials

<AccordionGroup>
  <Accordion title="Credentials by environment" icon="key" defaultOpen>
    * Use sandbox credentials only for testing.
    * Do not mix preproduction and production credentials.
    * Restrict administrator access to the panel where keys are configured.
  </Accordion>
  <Accordion title="Secure back office" icon="lock">
    * Keep the CMS, plugin, module and dependencies up to date.
    * Use individual administrator accounts, not shared accounts.
    * Review logs without exposing sensitive customer data.
  </Accordion>
</AccordionGroup>

## Order operations

<CardGroup cols={2}>
  <Card title="Consistent states" icon="database">The order state must reflect the actual payment state, not just the screen the customer saw.</Card>
  <Card title="Asynchronous methods" icon="clock">For QR, transfers, Cuotéalo or PagoEfectivo, wait for final confirmation before releasing the order.</Card>
  <Card title="Support logs" icon="file-lines">Keep the operation number, state and date for traceability with the integration team.</Card>
  <Card title="Controlled tests" icon="flask">Validate approved, declined and pending payments in sandbox before going live.</Card>
</CardGroup>

## Before going live

* Set the plugin or module to production mode only when appropriate.
* Confirm that enabled methods match those approved for the merchant.
* Validate emails, return pages, customer messages and order states.
* Prepare the minimum test evidence for final review.

## Core checklist

<AccordionGroup>
  <Accordion title="1. Preparation" icon="key" defaultOpen>
    * Credentials received for the target environment.
    * Merchant configured with enabled payment methods.
    * Administrator access to your CMS platform.
    * Correct plugin or module available for installation.
  </Accordion>
  <Accordion title="2. Functional configuration" icon="gear">
    * Keys and credentials entered correctly.
    * Return URLs and confirmation pages reviewed.
    * Currency, country and payment methods configured correctly.
    * Sandbox mode active before validating purchases.
  </Accordion>
  <Accordion title="3. Purchase flow" icon="cart-shopping">
    * Approved purchase validated end to end.
    * Declined purchase validated with a visible customer message.
    * Asynchronous methods tested when enabled.
    * Order confirmation aligned with the actual payment state.
  </Accordion>
  <Accordion title="4. Operations and back office" icon="table-columns">
    * Order states reviewed in the admin panel.
    * Plugin logs available for support.
    * Reversals, voids or refunds reviewed where applicable.
    * Emails, messages and post-payment pages reviewed.
  </Accordion>
  <Accordion title="5. Production" icon="rocket">
    * Sandbox validated before using production credentials.
    * Controlled production flow reviewed with the team.
    * Enabled methods match those approved for the merchant.
    * Integration ready to go live.
  </Accordion>
</AccordionGroup>

## Platform-specific checks

<Tabs>
  <Tab title="WooCommerce">
    <CardGroup cols={2}>
      <Card title="Plugin and credentials" icon="wordpress">Check installation, plugin activation and key configuration.</Card>
      <Card title="Checkout and order" icon="credit-card">Check that checkout displays valid methods and that order states change correctly.</Card>
    </CardGroup>

    * Validate an approved purchase with the correct redirect or final confirmation.
    * Validate a declined purchase with a clear customer message.
    * Confirm plugin logs are available for support.
    * Review asynchronous method behavior when enabled.
  </Tab>
  <Tab title="PrestaShop">
    <CardGroup cols={2}>
      <Card title="Module and hooks" icon="store">Confirm that the module is active and available in the correct checkout.</Card>
      <Card title="Order states" icon="clipboard-check">Check that the order reflects the payment state after a response or notification.</Card>
    </CardGroup>

    * Validate module installation and configuration in Back Office.
    * Confirm the customer experience for approved, pending and declined payments.
    * Review automatic state updates and module logs.
    * Test reversals or operational validation if the flow supports them.
  </Tab>
  <Tab title="VTEX">
    <CardGroup cols={2}>
      <Card title="Merchant configuration" icon="shopping-cart">Review credentials, payment conditions and connector configuration for each environment.</Card>
      <Card title="Payment flow" icon="arrow-right-arrow-left">Verify that VTEX checkout completes payment and reflects the result correctly.</Card>
    </CardGroup>

    * Validate payment methods and conditions in VTEX.
    * Review approved purchases and retry or decline behavior.
    * Confirm consistency between the order, payment and gateway response.
    * Complete functional tests before final certification.
  </Tab>
</Tabs>
